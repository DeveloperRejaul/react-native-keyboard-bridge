# ADR-010: Flatten `packages/react-native/` to `src/`

## Status
Accepted (maintainer-requested).

## Context
ADR-006 consolidated four separate workspace packages into one, but left it nested under
`packages/react-native/` — a shape inherited from the old multi-package workspace layout, where
`packages/*` made sense as a glob over several sibling packages. Since ADR-006, there has only ever
been one published package, so that nesting no longer serves a purpose: it adds two folder levels
(`packages/` and `react-native/`) to reach the package that *is* the repo, and its inner
pure-TypeScript folder was also named `src/` — the same name conventionally used for "the package
root that contains android/ios/bin," which reads ambiguously once the package itself lives at a
path also called `src`.

## Decision
1. `packages/react-native/` → `src/` (repo root). Only one workspace package exists, so the root
   `package.json`'s `workspaces.packages` is now `["src", "example"]` (an explicit path, not a
   `packages/*` glob).
2. `packages/react-native/src/` (the pure-TypeScript folder: `bridge.ts`, `settings.ts`,
   `gestures/`, `layouts/`, `prediction/`, `index.ts`) → `src/core/`.
3. `android/`, `ios/`, `bin/` keep their names, now direct children of `src/` instead of
   `packages/react-native/`.

Every internal config that referenced the old paths was updated: the package's own
`tsconfig.json` (`rootDir`/`include`/`exclude`: `src` → `core`; `extends` path shortened by one
`../` level since the package moved up one directory), `tsconfig.eslint.json`, `jest.config.js`
(`testMatch`), `package.json`'s `lint` script, and the root `package.json`'s workspace glob.
Doc/config path references (`README.md`, `CONTRIBUTING.md`, `AGENTS.md`, `docs/api.md`, prior
ADRs' path mentions, `example/index.js` and `example/metro.config.js`'s comments) were updated to
match; historical ADR text describing the *pre-ADR-006* multi-package layout (`packages/core`,
`packages/android`, `packages/ios`) is intentionally left alone — those paths were real at the time
those ADRs were written and aren't part of this rename.

## Consequences
- Purely mechanical — no behavior, build output, or public API changed. `main`/`types`/`bin`/
  `files` in `src/package.json` are unchanged (`dist/index.js`, `dist/index.d.ts`, `bin/cli.js`,
  etc.), since those are relative to the package root, which kept everything else's relative
  shape — only the package's own directory name and its inner TS-source folder's name changed.
- The `node_modules/react-native-keyboard-bridge` symlink (yarn workspaces) is regenerated by
  `yarn install` after the workspace glob change — anyone with a stale install must re-run
  `yarn install` from the repo root.
- Verified: `yarn install` re-links cleanly, `yarn build`/`yarn test` pass, and a clean
  `xcodebuild`/`./gradlew :app:assembleDebug` both succeed against the moved `ios/`/`android/`
  native sources.
